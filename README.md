# 阅卷助手网页版

给多位助教使用的统一批改工作台。首页只有试题、参考答案、评分细则、本地答题卡文件夹和 OpenAI API key 五项主要输入；高级参数折叠。答题卡为每位同学一份扫描 PDF，首页识别手写姓名、学号，其余页面自动对应题目。每题只调用一次评分，默认同时处理4个请求。自动输出 AI 建议成绩，人工复核可选，按学号查看和改分，改判理由允许留空。

访问方式：拿到网址即可打开，无需安装、登录或下载程序。[打开在线网站](https://probability-grading-assistant.zestyhinny18.chatgpt.site)。每位助教使用自己的 API key，自己的批次进度保存在自己的浏览器中。网站未内置付费密钥或学生材料。

## 助教操作

1. 先用右上角“先体验演示”熟悉流程。演示材料与分数均为合成，不调用 API。
2. 上传教师提供的试题、参考答案和评分细则，支持 PDF、DOCX、PNG/JPEG/WebP、UTF-8 文本。每个文件最大 3 MiB，三份材料合计最大 6 MiB。
3. 选择包含各学生完整扫描 PDF 的文件夹，填写自己的 OpenAI API key，确认材料处理后点“整理评分规则”。这一步会产生 API 费用。核对生成的题号、满分和评分点，再开始批改。材料缺失或冲突会提示补充，不能静默猜分。
4. 六位助教应使用同一份经负责人核对的规则：第一人下载“统一评分规则”，其余助教直接导入，避免反复整理或细则漂移。
5. 按“先检查PDF页数”可在不调用 API 的情况下查看收件情况；正式开始后，先识别首页姓名学号，再按题批改。等待结果，保持网页打开。可暂停、下载进度备份和导出建议成绩 CSV。建议成绩不要求逐题人工复核。
6. 需要时输入学号，点“查看 / 改分”。选择逐点评分、填写复核人即可保存，理由选填。重新打开页面后，重新选择原文件夹即可查看原图及改分，无需 API key；只有继续调用 API 才需要密钥。

## 文件夹要求

```text
本批答卷/
  2026000001.pdf
  2026000002.pdf
  2026000003.pdf
```

以上学号为命名示例。每位学生一份 PDF，原则上命名为“学号.pdf”。如果有 m 道题，每份必须是 m＋1 页：

| 原PDF页码 | 用途 |
| --- | --- |
| 第1页 | 身份首页，读取学生手写姓名、学号；忽略授课教师、分数表、考试纪律等无关内容 |
| 第2页 | 第1题（Q1）作答 |
| 第3页 | 第2题（Q2）作答 |
| … | … |
| 第m＋1页 | 第m题（Qm）作答 |

教师规则须按 Q1、Q2、…、Qm 连续排列。浏览器自动检查并拆页，不需要助教手动拆 PDF 或建立题目子文件夹。整份 PDF 最大64 MiB，自动拆出的每页最大3 MiB。加密、损坏、无法安全拆分的交互PDF、页数不符或某页过大，会单独列出错误；其他合格答卷仍可处理。页数不符时不能判断缺在哪一题，因此该份不凭页位猜分，也不填零；修复原PDF后建立新批次。扫描图中若页序本身颠倒、错扫且总页数相同，单靠页数检查不能证明正确，助教仍需保证扫描顺序。

## 姓名、学号与成绩表

- 身份首页与评分页分别发送。姓名、学号仅用于本浏览器的对应关系和导出，不作为评分条件；评分请求不包含首页、学生姓名或实际学号。正文图像自身如果写了身份信息，软件不会自动遮盖。
- 少数 PDF 漏改文件名时，使用首页清晰识别的学号补齐。不按文件顺序、常见姓名或学号规律猜测。
- 文件名学号与首页识别学号不一致、两份 PDF 对应同一学号、或无法确定学号时，暂不采用该份建议成绩。在“PDF收件与姓名识别”列表中查看首页、更正身份，无需说明理由。明确的学生归属是分数对应正确的前提；逐题人工复核仍然可选。
- 姓名读不清或未填写时姓名列留空并提示，不影响已确定学号的正常评分；可在查看首页后补录。清晰识别的姓名与人工更正值分别记录来源，不自动编造姓名。
- 建议成绩 CSV 包含学号、姓名、姓名来源、姓名识别状态、身份状态、原PDF文件名、各题分数、建议总分、分数来源和评分提示。学号在程序与备份中保持字符串；用 Excel 导入CSV时可将学号列指定为文本，避免自动数字转换。
- 若整份PDF漏收，软件无法从现有文件推断该学生；“更多设置”可填应收学号名单，导出将列出未收到PDF的学号及空分数。
- 当前程序使用新的单次评分数据格式（formatVersion 3）。旧批次和旧备份不再读取或自动转换；统一评分规则文件可重新导入后建立新批次。升级不会主动删除浏览器内旧记录，但它们不能在新版续跑。

## 保存、费用与恢复

- 整份PDF在浏览器本地读取和拆页，按需产生单页，避免整批拆页同时占内存。身份首页先发送给本站处理接口并转发 OpenAI 识别姓名、学号；作答页另按当前题目发送。本站没有答卷数据库、文件存储或共享批次列表；身份映射与识别结果留在本浏览器，评分模型收到的是本题规则及匿名证据编号。OpenAI 的数据处理按其服务政策执行。
- 密钥只保留在当前页面内存和本次 HTTPS 请求中；应用不会将其写入浏览器持久存储、日志、导出或源码。刷新后重新填写，不要把密钥发到聊天或成绩文件。
- 本地进度记录规则、整份PDF与单页哈希、首页识别结果及人工更正历史、评分结果、请求编号、API 原始结果和用量。进度备份和 CSV 可能含姓名、学号、作答描述，应保存在助教自己的受控位置。
- 每份结果返回后立即保存响应、用量和评分，所有保存按顺序执行，先后返回顺序不同也不会覆盖其他题结果。保存失败会停止补发并等待其余在途请求返回；已返回结果保留在当前页面，可下载进度备份。
- 暂停、断网、限流或服务器异常时停止补发，已在途请求仍等待返回并保存。请保持页面打开直至这些请求结束；联网后手动继续。关闭或刷新网页会中断等待，已发出的请求可能已经计费；重新进入后将没有完整响应的请求标为费用未定，保留预留且不自动重发。已保存成绩和人工改分会保留。文件需重新选择，按路径和 SHA-256 核对后续跑。整理好的规则草案在尚未开始批改时也能恢复，但需要重新核对确认。浏览器清理数据会丢失本机进度，请定期下载备份。换电脑需导入备份并携带原答卷；已收费但响应丢失的调用不能保证找回。
- 默认同时处理4个请求（可在开始前改为1或2个），一个完成并保存后补入下一项。先完成本批首页识别，核对重复学号，再并发处理每题的一次评分。人工改分优先。使用模型 `gpt-6.1-terra`，medium，最多8000输出token。
- 默认本批预算100元、每次预留5元；身份识别和规则整理也计入预算。发出请求前，将请求编号、状态和费用预留一同保存。预算检查始终包括已知费用、全部在途请求和费用未定的预留；预算只够2个时最多先发2个，等待完成结算后再补，不为凑足4个突破预算。
- 费用是按用量和程序费率估算，人民币系数 7.5 仅作预算，实际以 API 账单为准。预算预留不能保证最终账单绝不超额；当前请求费用可能超过预留。无法确认费用时保留预留并提示核查。无自动重试、无后台执行。
- 每个服务实例最多同时处理4个请求，繁忙时明确返回“未发出API”，本次不预估已用费用；助教稍后手动重试。各助教仍可能争用服务器或共享OpenAI项目限额；默认4个并不保证六人持续同时24个，也不代表真实压力验收。
- 同一浏览器通过 Web Locks 限制一个批处理运行，再对批次加锁；另一个标签页不能同时启动同一批或另一个批次，整理规则也使用相同运行锁。重新进入时先读最新已保存记录，避免旧标签重复提交。导入备份时若本机已有同一批次，会恢复本机记录并明确提示，防止旧备份覆盖已付费结果。不同浏览器、不同电脑不共享此锁，不能各自导入同一批并同时运行。建议最新版Chrome或Edge。

## 当前验证范围

已实现单次评分、默认4并发、逐次保存、断点恢复、费用账本、可选复核、CSV与进度备份。147项离线测试、类型检查及生产构建通过；Chrome已核验默认4并发、单次评分展示、空理由改分和刷新恢复。离线验证涵盖乱序响应、预算争用、保存失败、断网与在途响应、重复启动、旧备份拒绝、PDF安全拆页和身份识别。测试使用模拟接口，不调用真实 API。没有真实手写姓名识别或评分的准确率、真实费用、六人并发或大规模性能实测；先做教师评分对照的小样，再决定正式批次。程序导出的是建议成绩，正式考试成绩由教师或授权助教实质审阅确认。

## 源码与重现

- `app/page.tsx`、`app/globals.css`：简化操作页和样式。
- `lib/grading/validation.mjs`：评分规则、分值、证据和建议分逻辑。
- `lib/grading/browser-workflow.mjs`：文件核对、浏览器账本、身份与评分队列、导出和演示。
- `lib/grading/student-pdf.mjs`：整份扫描PDF检查、匿名单页拆分与按需读取。
- `lib/grading/identity-validation.mjs`：姓名学号识别结果校验。
- `lib/grading/api-service.mjs`、`app/api/`：无状态 OpenAI Responses 接口。固定官方地址、禁止重定向、不接收自定义服务商地址；不记录请求内容。
- `tests/`：离线验证。运行 `node --test tests/*.test.mjs`；类型检查 `node node_modules/typescript/bin/tsc --noEmit`。
- 网站使用 Sites Vinext 模板。需 Node 22.13+，先运行 `npm run install:ci`，开发 `npm run dev`。通过已安装 Sites 插件的 `build-site.mjs` 与 `site-workflow.mjs` 构建、同步并发布；自建部署应在自己的账户注册站点，再配置 `.openai/hosting.json`。这是带服务端接口的网站，不能仅上传到静态 GitHub Pages 就完成 API 处理。
- 本仓库仅包含网页程序、构建依赖声明、说明及合成测试。公开源码不含现有网站的部署编号；不要加入学生文件、导出、密钥或本机运行状态。`.sites-runtime/`、`dist/`、`node_modules/` 是可重建且已忽略的本地依赖与构建目录。

PDF本地处理使用 [pdf-lib](https://pdf-lib.js.org/docs/api/classes/pdfdocument)。官方接口依据：[模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-terra)、[文件输入](https://developers.openai.com/api/docs/guides/file-inputs)。费率为 2026-10-29 核对的快照，不保证以后不变。
